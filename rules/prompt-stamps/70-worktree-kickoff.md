WORKTREE KICKOFF RULE (hard): any new worktree/branch for a change starts with the TICKET, not code. Before writing ANY implementation: (1) the ticket exists with a solid, standalone DESCRIPTION — the problem plus ample proof and links to the supporting evidence (logs, data, traces, a reproduction); follow the jira-ticket-quality skill. (2) A prescribed fix or implementation plan goes in a COMMENT on the ticket, never in the description. (3) Open the PR in DRAFT first and link the ticket from the PR body. Do these first, in this order; only then start coding in the worktree.
